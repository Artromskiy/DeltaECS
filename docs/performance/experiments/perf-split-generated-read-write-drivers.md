# Split generated read/write drivers experiment

Status: **validated candidate; merge deferred**.

Branch: `perf/split-generated-read-write-drivers`

Baseline: `fb6c8d0b4b87511ac121eff74c84956da96c94d2`

Source commit: `4a8db123d57ab0de6785ad88b828cf9a4a4f317f`

## Hypothesis

Dispatch generated query execution once into separate read-only and write
drivers so `hasWrites` and write tick/stamp state are absent from the read
plan/chunk flow. Keep the public generated `ForEach` API, consumer-generator
contract, type-erased plan and row boundaries, query/world ownership, lease
lifetime, write stamps and empty-query behavior unchanged. The public dispatch
is small; both loop drivers are explicitly non-inlined.

## Source change

- `World.ExecuteGeneratedForEach` performs one read/write dispatch.
- `ExecuteGeneratedReadForEach` constructs slots without write state.
- `ExecuteGeneratedWriteForEach` retains reserve-before-lease ordering and
  reserves a write stamp only after finding a non-empty chunk list.
- `GeneratedQuerySlots` gained an internal read-only constructor; its public
  shape and generated invoker contract did not change.
- A regression test proves that a generated write over an empty query does not
  advance the world stamp.

No existing component-bearing generated read-only BDN probe was available, so
no new benchmark surface was added. The existing `Movement4ApiComparison`
Functor and Delegate methods are the write guardrail.

## Serialized BenchmarkDotNet comparison

The exclusive run used BenchmarkDotNet `DefaultJob`. The existing
`Movement4ApiComparison` Params were restricted identically and temporarily to
100, 1,000 and 1,000,000 in both worktrees. The benchmark edits were restored
after measurement and are not committed. Baseline completed first, then the
candidate; no other BDN process ran concurrently.

Only the existing non-context `Functor` and `Delegate` methods were selected.
The Error column is BDN's half-width 99.9% confidence interval. Lower
candidate/main ratios are faster.

## Invalid concurrent BDN run — excluded

A default-job baseline run for the existing non-context `Functor` and
`Delegate` methods was started with all six existing Amount parameters. Other
agents then started BDN on the same machine. The run was interrupted with exit
code 130 and is excluded in full: no Mean, Error, StdDev, allocation or ratio
from it is evidence for this experiment.

Do not use `artifacts/micro/split-drivers-baseline` for performance claims. The
valid replacement is the serialized pair documented above.

## Verdict

**Merge deferred.** The split removes one branch, one compare and 8 B from the
generated write driver, reduces the Movement4 Functor wrapper by 4 B, and
delivers a reliable 1.567% Functor improvement at Amount 100. Larger workloads
and the Delegate route are neutral within uncertainty, with no allocation,
correctness, ownership, lease, write-stamp or empty-query regression.

The candidate's primary design benefit is a thinner generated read-only driver,
but this round had no direct component-bearing read-only benchmark. Add that
workload before deciding whether to merge the source commit.
